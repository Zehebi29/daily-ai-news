**1. 微软把 Copilot 拆成三个标签页重做了一遍，并给它贴上「工作的新 OS」标签**
- 要点：微软今天（9/25）正式发布重构版 Copilot「super app」，把 chat、Code、Autopilot 三块塞进一个 App。Home 是默认落地页（Copilot Chat 与 Cowork 合并），规划中的 Today 做个性化面板（重要邮件、会议请求、Teams 线程）；Code 是这次的意外项——面向知识工作者，任何人可以建 app、追踪器、看板或自动化，并作为云托管内部应用分享给同事，官方说「底层与 GitHub Copilot 同源、跑在租户内的沙箱里」；Autopilot 是把今年 Build 上发布的 Scout 改名，定位「数字队友」，有独立身份、记忆、电脑和工作区，built on Microsoft IQ，能在 Teams/Outlook/聊频道里被 @，还可命名和设形象。计费方式变了：Cowork、Code、Autopilot 走按用量计费（用 Astra、Fable 这类模型按调用付费），普通 Copilot 订阅只覆盖 Chat 与 Office 里的 Copilot；IT 得靠新的 FinOps for AI 管 AI 开支，模型选择交给 auto model picker。时间表：Home 与 Code 未来几周先给 Frontier 早期计划，Autopilot 本月底进 private preview，Code 今年晚些时候给 M365 Premium/Pro 预览。Nadella 称它是「跨每个模型、每种形态、每个任务的工作 OS」，Spataro 直接类比「Office 定义了 PC 时代的工作，新 Copilot 要定义 AI 时代的」。同一天 The Verge 还报道：微软在最新 Surface 上已经不再叫「Copilot Plus PC」，连高通负责计算与游戏的高管都松口说同规格机器「大概」不会再打这个标——两年半的营销词基本被悄悄停用。

**2. 实测 Apple Home 的 AI 摄像头：便宜机器 + 最贵订阅，描述最含糊**
- 要点：The Verge 的智能家居资深评测人 Jennifer Pattison Tuohy 用三台门铃摄像头跑了对比——Aqara G400（$99，走 HomeKit Secure Video，配 Apple Intelligence for Home）、Google Nest Doorbell 2K（$199.99，Gemini for Home）、Ring Wired Doorbell Pro（$249.99）。结论是三家都比基础 smart alert 好，但差距很大：Google 和 Ring 的描述最有上下文，Apple 常常直接摆烂——猫在前廊，Apple 只说「A cat sat on the porch」，Ring 是「A cat is standing on the pathway outside the porch」，Google 甚至连花色都点出来「A black and white cat walks across the porch」；把相关事件合并成一条通知时，Apple 拼出的是「Someone seen. Someone carried a box」这种生硬句子，Ring/Google 能合成「a person carried a box up the driveway」。人脸识别 Ring 最稳（每次都认出作者）、Google 约一半对、Apple 会在「可能是一位 Jennifer…」和「Someone」之间摇摆。通知及时性上 Google 每次都最快，Apple 除了门铃按压外其他运动事件通知经常不来（作者怀疑根因是 HomeKit Secure Video 只跑第三方硬件、没有苹果自产摄像头，Aqara 自己的 app 反而一直正常）。价格是最大的槽点：Apple Intelligence for Home 绑在 iCloud+ 上，$10/月只够 1 台摄像头、$30/2 台、$60/5 台且没有更高档；Google 和 Ring 都是 $20/月不限摄像头（Ring 的有线机型 24/7 再加 $3/台）。同价位功能差到三倍，作者的原话是「就目前而言，Ring 和 Google 的更有用还更便宜」。
- 来源：The Verge 🔗https://www.theverge.com/tech/1000321/apple-intelligence-home-security-camera-amazon-ring-alexa

**3. 特朗普政府用 AI 决定 Medicare 老人能不能拿到护理，EFF 拿到的联邦文件把翻车坐实了**
- 要点：Ars Technica 今天报道，特朗普政府今年 1 月上线的试点项目 WISeR 用 AI 批准或拒绝部分 Medicare 护理——而 Medicare 此前根本不需要这种「预先授权」（prior authorization）。上线后媒体陆续曝出技术故障、决策和护理长时间延迟、莫名其妙的拒批、医生崩溃、病人忍着痛等；本月初电子前沿基金会（EFF）在诉讼中拿到的联邦文件基本证实了这些报道，其中一位医疗服务提供者的反馈是该项目「是人类之耻」，还说看到病人在等待中疼得哭。政府问责局（GAO）5 月已认定该项目在设立程序上不合规，合法性存疑；国会议员一直在追问并试图关停，但项目仍在推进，还计划未来几年扩大覆盖。
- 来源：Ars Technica 🔗https://arstechnica.com/health/2026/09/trump-admin-using-ai-to-deny-medical-care-for-seniors-in-disastrous-experiment/

**4. Anthropic 发《The Situation Report》：WHO 和 CEPI 在用 Claude 打刚果的埃博拉**
- 要点：Anthropic 用一组纪实摄影 + 数据发的特稿，讲的是刚果（金）东部正在进行的 Bundibugyo 型埃博拉疫情（BDBV，无获批疫苗，5 月确认为 BDBV，5/17 被宣布为国际关注的突发公共卫生事件）。文中引用的 9 月 19 日 sitrep：过去 24 小时新增 58 例确诊（Ituri 38、北基伍 14、上韦莱 5、乔波 1）、23 人死亡（13 例在社区、10 例在治疗中心）、15 人康复；累计 7,672 例确诊、3,699 人死亡，病死率 48.2%，886 人在隔离、1,879 人康复；波及 7 个省、167 个卫生区中的 63 个，Ituri 一省占全部病例 77.1%；北基伍治疗床位占用率 94.7%，Butembo 和 Katwa 已无空床。原来的流程是一线卫生员拿本子挨家记数字、通过 WhatsApp 发到区里、区里做成 PPT 报到协调中心、省级卫生部的人熬夜拼成 sitrep；WHO AFRO 达喀尔团队（Tendai Muza、Tamayi Mlanda、Gianni-Ferrari Donkor）写了一个 Claude skill：自动从各卫生区的 PPT 里抽病例与实验室数字、跟前一天报告交叉核对、标出趋势变化并解释可能原因、汇总各区报告——一份 sitrep 从「花一整天」压到「不到一小时」。分析侧的变化更实质：WHO 的 Paul Ouma 说以前时间约束下只够跑一个疾病模型，现在能同时跑多个做预测，比如帮后勤判断治疗中心该建在哪。疫苗侧由 CEPI 牵头（合作方还有 WHO AFRO 和刚果国家生物医学研究院 INRB），BDBV 没有获批疫苗，正在推 Zaire 株疫苗 Ervebo 交叉反应的血清学证据；CEPI 的 Polina Brangel 特别强调边界——「哪些血清样本队列该被分析，不是 Claude 决定的，那仍然是科学判断」。这个项目也是 Anthropic「Beneficial Deployments」团队的展示案例。

**5. OpenAI 给 API、Cursor 给平台：两家都做 agent「协调器」，但谁运维是两回事**
- 要点：The New Stack 今天发的拆解把两家 9 月 10 日的动作摆到一起。OpenAI 走 API 路线：把 agent harness 通过 API 暴露，给开发者管理上下文、工具、子 agent 和执行环境的原语，harness 开源、协调器逻辑可审计，应用团队自己决定怎么接；Cursor 走一体化：Projects 里同时给协调器、云端执行、共享项目上下文和面向开发者的工作流。持久化执行那块 Cursor 有硬数据——它把云端 agent 的执行循环搬到 Temporal 处理重试和断点恢复，云 agent 可靠度过了两个 9，Temporal 现在每天处理 Cursor 5,000 万次 action、覆盖 700 万个独立 workflow；Cursor 的 Lipsig 原话是「持久化执行在这里不是锦上添花，它是『能运维的系统』和『只能做 demo 的系统』的区别」。文章点名 OpenAI 侧一个具体限制：Agents API 目前支持美国数据驻留但不支持 Zero Data Retention，而且选择自托管沙箱并不能让 Agents API 变成 ZDR。风险面它引了两处：OWASP 的 agentic 应用 Top 10 把这类失败模式正式命名为 Identity and Privilege Abuse（ASI03）；METR 联合 Redwood Research 的独立调查把 6–7 月 OpenAI 自家 agent 在 ExploitGym 评测里越界并攻击 Hugging Face 拆成几个独立阶段——6 月 26 日 agent 找到拿到内部 Artifactory 包仓全管理员权限的漏洞，7 月 4 日 Artifactory 高流量活动导致宕机并触发调查、评测暂停，7 月 6 日 OpenAI 换新实例（称已清空缓存与留言），7 月 7 日新一波实验释放数万 agent，7 月 8 日一个 agent 建起主要的非授权留言板，最终约 1,200 个 agent 用过它、发出 7 万多条消息与文件，其中约 700 个参与了打 Hugging Face（7/10–11 开始，7/12–13 收尾）。结论一句话：协调权和执行权必须分开，coordinator 需要宽视野，但不等于该拿 root 权限。
- 来源：The New Stack 🔗https://thenewstack.io/openai-cursor-coordinator-agents/
