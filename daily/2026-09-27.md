**2. DeepSeek 放出 DSec：给 agentic 训练做的生产级沙箱平台，一个单元 160 节点、每天约 300 万个沙箱**
- 要点：arXiv 2609.22978《DeepSeek Elastic Compute (DSec): A Sandbox Infrastructure for Effective Agentic Training at Scale》，31 页 13 图，19 日提交（是早前两页 extended abstract 的大幅扩写版，投稿 ACM SIGOPS ATC 2026 Operational Systems Track）。解决的问题是：大规模 agent 训练/评估要的是隔离、有状态、突发创建、长时间保留状态的执行环境，靠单个 sandbox runtime 撑不住，得要一层弹性执行平台。DSec 用一个统一 SDK 暴露 FnCall / 容器 / microVM / 整机 VM 四种后端，在集群级别做放置和生命周期管理，用可独立版本化的层去拼环境，把内存共享、回收和 CPU 调度合起来做高密度执行，镜像数据从集群级分布式文件系统 Fire-Flyer File System (3FS) 按需加载。关键是与 RL 框架协同设计：把有状态的 rollout 执行和可被抢占的 GPU 训练解耦，训练和沙箱生命周期联动，既保住 rollout 状态又回收空闲资源，并明确写了要缓解 reward hacking 这类 agent 失范行为。规模：单个生产单元约 160 节点、每天约 300 万个沙箱、生产上支持 38 万+ 并发沙箱、每秒新建 5,000+ 个。和第 1 条正好构成一体两面——前端是"怎么防止 agent 失控"，这里是"怎么把 agent 大规模跑起来还不出事"。
- 来源：arXiv https://arxiv.org/abs/2609.22978 · HN 274 分 https://news.ycombinator.com/item?id=49859112

**4. 「决策模型」这波开始往本地和开源走：Ollaya 开源本地运行时 + 把 GLM-5.3-Flash 改成 Jev-like**
- 要点：TypeSafe 的 Jev（单次前向输出校准概率、不做逐 token 生成的 System-1 决策模型）这周从"一个新物种"变成了被对标、被复刻的对象，两条新进展：①Ollaya（HN 597 分，独立开源项目，明确声明与 Ollama、TypeSafe 无关联）把自己定位成"本地跑决策模型的 Ollama"：同一条请求问五个带类型的问题，winnow:e4b 在 RTX 4090 上 89ms 端到端、typed decisions 准确率 0.722（托管版 Jev 0.738），更小的 laya 约 10ms、CPU 上就能跑，数据不出本机。②Privatemode 直接拿 API 把 GLM-5.3-Flash 调成 Jev-like 决策模型，在 29 个公开带标注数据集上和 TypeSafe 的 Jev、Convai 的 Laya 三方对比，方法、冻结数据集规格、harness 和聚合口径全部开源可复现，还给了 GitHub 仓库和一段可丢给 Claude Code / Codex 的 prompt 来自己搭。值得跟的点：agent 的"判断层"正在从闭源托管模型变成本地可跑、可自己拿开源模型改造的小模型，成本和隐私都往使用者这边移。
- 来源：Ollaya https://ollaya.dev/ · HN 597 分 https://news.ycombinator.com/item?id=49848269 · Privatemode https://www.privatemode.ai/blog/system-one-from-glm-flash · HN 105 分 https://news.ycombinator.com/item?id=49857656

**5. Meta 的 Muse 很可能在后台跑 OpenAI 的模型，还带着 Anthropic 的管线**
