**1. ZCode 偷偷把你整个 Git 历史打包传上阿里云，密钥只有 Z.ai 有**
- 要点：开发者 ferstar 今天放出逆向记录：Z.ai（智谱）的 AI 编程桌面端 ZCode 只要处于登录状态，就会把整个工作区——完整 .git 历史、LFS 资产缓存、reflog 和全局应用配置——打包加密后上传到阿里云 OSS。他的抓包数据：345MB 商业工作区打成 313MB 加密包、42,411 个文件，调查期间还记录了 564 次上传失败重试。加密方式是信封加密，载荷用对称密钥加密、该密钥再用 RSA-OAEP 公钥包起来；公钥在上传凭证协商时由服务端下发，对应私钥只存在 Z.ai 云端——ferstar 试遍本机所有私钥都解不开，也就是说这坨 313MB 密文连 ZCode 客户端自己都读不了。他的结论一句话："一把只有服务端能用的钥匙只有一个用途：确保服务端能随时读你的代码。"帖子数小时 27.6 万浏览，中文提醒帖另有 6.38 万。评论区暴露一个真实混淆：不少人以为 GLM 开源所以 ZCode 也开源——权重是开的，harness 是闭的。被引用最多的一句来自 Petri Kuittinen："我的建议一直是、也仍然是：不要信任闭源 AI harness。"

**2. Bend 2 号称"用数学证明挡住 AI 错误"，今天被人拆出踩了 vibe-coding 陷阱**
- 要点：Bend（昨天 HN 511pts/243 评论）的定位是"AI 编程时代的语言"：speed of C + CUDA 并行 + Lean 式证明 + Python 语法，人写 laws、AI 写实现和证明、编译器验证明，官网一句 "Enjoy bug-free, fast vibe-coded apps!"，LAWS.bend 相当于"带证明的 AGENTS.md"。今天 Liam Powell 发批评文《Bend 2 and the Vibe-Coding Trap》：Bend 首页那个"玩家不可能赢"的 2D demo，光声明这条 law 就写了 58 行，LLM 为了证明它又写了 442 行 PROOF.bend（更别说 LLM 还能重定义 Game 的子程序）；而整站和代码库里 "formal verification" 这个词一次都没出现——他用 LLM 把同一个 demo 在 SPARK（现成的形式验证语言/编译器，Ada 生态）里重做了一遍当对照。他的结论比 Bend 本身更值得记：vibe coding 让人可以在"还没学到足以判断有没有更好解法"之前就把一大坨方案建完——一整门语言和编译器都能这么造出来。

**5. PrismML Ternary Bonsai 2 27B：27B 级模型塞进 5.9GB，保留 98.2% 能力**
- 要点：基于 Qwen3.8 27B，三元权重 {−1, 0, +1} + FP16 分组缩放，加权平均 1.76 bit/权重，端到端全模型低比特化，总体积 5.9GB（比全精度版本小 9 倍多），262K 上下文、支持图文多模态输入、Apache 2.0 许可。官方基准聚合分 83.9，保留基座 98.2% 的聚合能力：instruction following 反超基座（82.66 vs 81.25），coding 基本持平（81.58 vs 82.17），agentic & tool calling 略有下降（77.57 vs 79.74）。半年前第一代 Bonsai 27B 只解决"能不能在本地跑起来"，这代的重点是把质量推到可用线；社区把它和昨天 TNS 报道的 Intel BITCOS（1.58 bit → 1.485 bit）并列为低比特本地部署的两条线。HN 484pts。
