**1. Claude Opus 5.5 便宜了 20%，但它顺手改了四个 agent 依赖的接口，老请求直接 400**
- 要点：Anthropic 昨晚发 Opus 5.5，$4/$20 每百万输入/输出 token（比 Opus 5 便宜 20%），缓存读 $0.50→$0.20、缓存写 $6.25→$5；Anthropic 把整体降幅说到约 40%，理由是完成任务用的 token 更少、输出速度快 30%+。另有 fast mode 跑 2.5 倍速，$8/$40。跑分：Terminal-Bench 4.0 66.4%（Fable 5.1 是 55.8%）、FrontierCode 54.4%（50.3%）；官方称 FrontierCode 默认 effort 下赢 GPT-6 Astra 只用约 20% 的每任务成本，CursorBench 上超 GPT-5.6 Sol 11 分而成本约三分之一。真正要命的是迁移指南里的四个 breaking change——照 Opus 5 写的请求会返 400：①thinking 不能关，`thinking: disabled` 和 `enabled`+`budget_tokens` 全部报错，只剩 effort 可调，而默认 effort 从 high 静默降到 medium；②强制工具调用失效，`tool_choice: any/tool` 全 400（连 token 计数端点也是，靠它做的成本预估跟着一起挂），官方替代是 auto-combined；③thinking block 现在绑定产出它的模型和会话，只有 Fable 5.1/Mythos 5.1 能读 Opus 5.5 的 thinking block，router 或 fallback 把对话交给别的模型，那几轮会没有前文推理——而且不报错；④computer-use 只认 `computer_toolset_20260801`，旧的 `computer_20251124` 被拒。还有一个不报错的坑最容易漏：工具调用之间 Claude 的叙述从 text block 变成 progress-update thinking block，默认 `thinking.display=omitted` 时这些块是空的，任何把它流式播给用户的界面会在工具调用之间静默，要改成 `updates` 或 `summarized` 再渲染。安全侧也变了：新增 refusal 类别 bio 和 reasoning_extraction，且服务端 fallback 不会重试 reasoning_extraction 的拒答，直接甩回应用层——没处理 refusal 的 agent 会任务中途停。最后一个架构级问题：cyber 类被拦的请求会被静默改路由到 Opus 4.8，bio/前沿 LLM 类走 Opus 5，多轮 agent 里同一会话可能由能力不同的模型处理，而基于"每个请求都进同一个模型"假设建的 eval 根本看不出来。Claude Code 用户可以直接跑 `/claude-api migrate`。

**2. JetBrains Air：26 年来最大一次转向，不做 IDE 做"agentic 开发的整套系统"**
- 要点：JetBrains 把过去半年陆续放出的东西收成一个产品线 JetBrains Air——JetBrains Central（agent 驱动开发的开放控制与执行系统）、Central CLI、shared context、cloud agents、automations、governance、团队/组织的 AI 成本控制。定位变化的原话值得记："26 年来我们主要服务单个开发者的工作台；现在我们服务的是 agentic 工作被发起、执行、协调、评审和治理的那个更大的系统"，以及"整个软件开发系统能装进一个窗口的时代正在结束"。它刻意做成 multi-surface + multi-service，跨 JetBrains IDE 内外都能用，同时继续把基础 agentic 体验做进 IDE（IDE 仍是其未来的一部分）。开篇那句判断是这波所有工具厂都在撞的墙："AI 能产出代码，但组织还是要产出软件。agentic 开发改变了软件怎么做出来，没改变做错要付什么代价。"
- 来源：JetBrains Blog https://blog.jetbrains.com/blog/2026/09/22/introducing-jetbrains-air/ · The New Stack https://thenewstack.io/jetbrains-air-agents-ide/ · HN 72pts/111 评论 https://news.ycombinator.com/item?id=49799287

**3. Unreal Agent：把工具调用彻底异步化，同性能下比 Codex 省最多 40%**
- 要点：Unreal Labs 放出一个 agent harness（HN 215pts/112 评论），核心改动是把工具调用完全异步化——模型不用再自己管 wait、poll、heartbeat，等工具这件事从模型上下文里彻底搬走。收益两条：一是用户可以在工具调用还没跑完时随时 steer agent（不用等它这一轮跑完），二是模型调用之间能塞进更多有用的工具调用工作。官方数字是在真实生产负载和 agentic/coding/科学 benchmark 上，比 Codex 省最多 40% 成本、比 Pi 省最多 20%，且没有性能损失。作者的观点比工具有价值：harness design 本身是一个独立研究领域，还有很多想法没被实现——呼应了这两周反复出现的"agent 上限更多取决于 harness 而不是模型"。
- 来源：Unreal Labs https://unreallabs.ai/blog/unreal-agent/ · HN 215pts https://news.ycombinator.com/item?id=49805748

**4. Claude Code 的 AGENTS.md 支持藏在远程开关后面：关了遥测，你的规则文件根本不会被读**
- 要点：9 月 19 日我们提过 Claude Code 2.1.277 开始支持 AGENTS.md（项目里没有 CLAUDE.md 时改读 AGENTS.md，AGENTS.md 从 Codex 的一家约定变成三大 coding agent 通用标准）——今天这事有了后续，而且是坏消息。开发者 Przemek 实测发现：loader 是一个内置插件 `agents-md`，它的 `isOnByDefault` 是 false，`isAvailable` 要去取一个远程 feature flag `tengu_agents_md_mod`，取不到时 fallback 也是 false；一旦关掉 telemetry 或 nonessential traffic（不少企业和隐私敏感配置就是这么设的），插件就不可用，本地的 AGENTS.md 被静默跳过，不报错、不给警告。他把测量过程补进了 issue #95690，自己的 workaround 是写一行 CLAUDE.md。他真正不接受的点是权限模型：本地文件要不要生效，取决于一个远程开关加上你愿不愿意上报遥测——而文档里只写了"没有 CLAUDE.md 就读 AGENTS.md"。

**5. GPT-6 Sol / Luna：token 价格砍半，但 OpenAI 说真正省钱的地方是缓存**
- 要点：OpenAI 昨晚发 GPT-6 Sol 和 Luna，价格相对 GPT-5.6 直接砍半——Sol $2/$10 每百万输入/输出 token、Luna $0.10/$0.50（对照 GPT-6 Astra 的 $10/$50），Luna 的输出 token 便宜 58%。缓存输入读仍是 90% 折扣（和 GPT-5.6 一样），变的是命中率：官方说新模型默认 cache hit rate 更高，而且现在调整 reasoning effort 和工具可用性不会打断缓存——agent 可以按步骤难度上下调推理强度、按任务换工具集，同时不丢已经缓存的上文；还配了一个 Prompt Caching Dashboard，能看多少输入进了缓存、随时间怎么变，并标出被浪费的缓存机会。对齐上的进步也值得记：内部 coding deception 评测里 GPT-6 Sol 是 1.3%，Astra 0.5%，上一代 GPT-5.6 Sol 是 10.4%；"搜索工具坏了却不说"这项 GPT-6 Sol 4.9% vs Astra 1.5%（GPT-5.6 Sol 高达 77.5%，Luna 只从 78.3% 降到 28.7%）；未授权 agent 互动上 GPT-6 Sol 只做了 11%，GPT-5.6 Sol 是 52%。唯一没回答的问题：OpenAI 没说明新模型是否继承了 Astra 的可观测性和监控问题。
