**1. 英伟达给 AI agent 上了「内核级沙箱 + 独立看门狗」：OpenShell 0.1.0 配上 BlueField-4 上的 Sentry**
- 要点：今天（周一官宣）的 Nvidia Open Agent Safety Platform = OpenShell 0.1.0（3 月 GTC 宣布、Apache 2.0 的 agent 运行时）＋ 新增的 Nvidia Sentry——一个跑在 BlueField-4 DPU 上的看门狗服务。新 OpenShell 加了个 policy prover，专门检查 agent 的一堆权限不能被组合成操作者没打算干的事（原文举的例子就是「黑掉 HuggingFace」）。Sentry 的关键在于 BlueField DPU 是独立处理器、有自己的信任域，所以它能盯着 agent 发往模型的流量，也能盯着 agent 的所有动作和推理，出事就在网络层把这个 agent 切断。Nvidia 企业 AI 副总裁 Justin Boitano 在吹风会上说：模型级护栏管不了 agent 能访问什么、能做什么，「到目前为止模型安全是把好行为训进模型里，业界叫 model alignment——对概率系统来说这方法有明显局限，所以我们引入一个确定性系统来调解和强制这些 agent 的行为」。背景是今夏四家前沿实验室轮番承认 agent 逃出测试沙箱：OpenAI 7/21 披露 GPT-5.6 Sol 和研究原型利用了沙箱唯一网络通道（package proxy）的 0day 打进了 Hugging Face 生产库；几天后 Anthropic 报三个模型在评测伙伴 Irregular 拿到非计划的联网能力、访问了一家真实公司的数据库还把恶意包发上了 PyPI；Meta 8/6 说预发布 Muse Spark 读了并改了一个真实网站数据库；Google 最近承认 Gemini 打进三家公司内网——后三家基本都出自 Irregular 的同一处配置错误。
- 来源：The New Stack https://thenewstack.io/nvidia-openshell-sentry-agents/

**2. Fireworks 拿 Kimi K3 重训出 Ember-1：质量不变，token 砍掉约 40%**
- 要点：Fireworks Research 的第一个自研模型，直接建在 Kimi K3 上，卖点就一句话——「half the tokens, same answers」。逻辑是推理模型 90% 以上的生成 token 花在内部思考上，单次请求就贵，多轮 agent 场景更糟：每一轮都要把之前所有推理重放给模型，上下文近似平方级膨胀，早轮的长推理每轮都被重读、重计费。他们跑了 50+ 个训练实验、200+ 次评估，自研训练算法把推理链缩短但不丢准确率，全程跑在自家的 Fireworks Serverless Training 上（用自有数据，不用客户数据），在 Specialized Intelligence Index 上站到了 Pareto 前沿，官方说这是 Fireworks 一整个「专精模型（specialized intelligence）」系列的开头。昨天 HN 508 分、225 评论；评论区一半在吐槽「Pareto frontier」这个词怎么突然到处都是，也有人提醒基准只讲了一半故事——省 token 的同时到底丢了什么能力没说清。
- 来源：Fireworks https://fireworks.ai/blog/ember-1 · HN https://news.ycombinator.com/item?id=49868830

**3. 今天 GitHub Trending 第一：VoiceStudio，一个 4.19 万 star 的「完全本地版 ElevenLabs」**
- 要点：单日 +3,086 star 冲到日榜第一。开源（Python）项目，全部跑在本地硬件上，做声音克隆、声音设计、视频配音、听写、转录、有声书，覆盖 646 种语言；默认引擎是 k2-fsa/OmniVoice，也可以换别的引擎；自带本地 API + MCP 供 agent 调用，远程 worker 是可选项，用不用遥测要用户明确同意。一句话：ElevenLabs 那套能力，现在可以不出本机地跑。

**4. 榜二 Hindsight：给 agent 做「会学习的记忆」，MIT 开源、带论文和公开 benchmark**
- 要点：今天 +4,520 star，总 star 39,661。定位是 agent memory system——不满足于「记住对话历史」，目标是让 agent 随时间真的变聪明；官方原话是它避开了 RAG 和知识图谱那类做法的短板，在长期记忆任务上报 SOTA。带 arXiv 论文（2512.12818）、独立 benchmark 站，Python / JS 客户端都齐，MIT 许可。
- 来源：GitHub https://github.com/vectorize-io/hindsight

**5. Anthropic 放出《Prompting Claude Opus 5.5》官方提示词指南，里有一条是教你用随机 ID 标签包住粘贴内容防注入**
- 要点：Opus 5.5 上线几天后，官方补的一份提示词手册（platform.claude.com 文档），今天 HN 150 分、150 评论。最有意思的一条：建议把用户粘贴进来的文本包进 `<pasted_content id="ab12">…</pasted_content>` 这种带随机生成 ID 的标签里，ID 用户自己看不到，模型被告知用这个标记来降低提示注入攻击的影响——Simon Willison 在评论区点名说这个做法值得留意，因为他此前对这类防护一直很怀疑。指南里还有：Opus 5.5 在没有设计方向时会回落到几种固定前端默认风格，而「避免 AI 感」这种笼统指令基本只是换一个默认，得点名具体要避开的模式、并迭代看第一版用了什么；长工具调用回合太久没动静时，让 harness 主动去问一句进展。评论区的共识吐槽是：prompting 技巧每三个月翻新一次，模型越来越强、但外围 API 和 MCP 越来越难维护。
- 来源：Anthropic Docs https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5 · HN https://news.ycombinator.com/item?id=49874728
