**1. Meta 把 WhatsApp Business 的开通流程交给 Claude / Codex：MCP 上生产，但 agent 没有自己的身份**
- 要点：Meta 昨天发布 WhatsApp Business Tools MCP server，开发者把 server 接到 Claude 或 Codex，用自己 Meta 账号登录、勾选允许 agent 访问的那几个 business（权限是按 business 收窄的，不是账号下全部）。之后的活基本可以一句话交代：给号码和显示名，agent 去把号码加进来、开好 WhatsApp 账号，Meta 用短信或语音发一次性验证码，开发者把码回给 agent，号码完成验证并注册为可发消息。再往下是模板（marketing/utility，能建、查、改、删）、发测试消息、以及配置把客户回复转出去的 webhook（CRM/客服/机器人/订单系统）；客户在 24 小时服务窗口之外时，agent 会提示自由格式消息发不了并改推已批复的模板。agent 也能只读地检查账号状态，比如是否缺 Meta 收费所需的支付信息。护栏这块 Meta 的说法很明确：agent 用的是连接者本人的权限，每次读取跑在本人 viewer context 下、每次调用都有日志，并且"任何改变状态的操作都要求一个经过认证的人，而不是 app 级凭证"——TNS 的解读重点就落在这里：agent 拿到了活，但没有自己的身份。背景数据：付费消息在 2025 年 Q4 已越过 20 亿美元年化 run rate（CFO Susan Li 在 1 月财报会上的说法）。Meta 产品市场 Zoë Lieberman 的官方口径："你描述想要什么，agent 去处理账号、号码、模板和 API 调用。"
- 来源：The New Stack https://thenewstack.io/meta-mcp-whatsapp-business-claude/ · TechCrunch https://techcrunch.com/2026/09/15/meta-now-lets-ai-agents-handle-the-boring-parts-of-whatsapp-business-setup/

**2. AWS 给出 agent 落地的另一条线：agent 只负责提方案，放行由确定性代码说了算**
- 要点：AWS 昨天放出一个 Step Functions 模式，把 Bedrock AgentCore 的专用 agent 编排起来，原则一句话——"agents propose, deterministic code validates"。做法不是让主管 agent 去分发子任务和调工具，而是把编排、扇出、校验、路由、重试这几件事从 agent 的推理里挪进 Step Functions：每个 agent 的非确定性行为外面套一层确定性步骤，任何 agent 都不能直接动手（写预订、发起支付都不行），只有确定性校验通过后提案才被应用；Step Functions 保留执行历史，供审计和复核。给的例子是航班取消后给几百名旅客重排行程这种"点鼠标点到手软"的活。同一天 AWS 还发了一份 Abnormal AI 的案例研究，主张 agent 需要一个能真正计算、处理数据、并在返回结果前自己程序化验证的计算环境——两条线指向同一件事：把不确定性关进可验证的壳里。
- 来源：The New Stack https://thenewstack.io/aws-agents-deterministic-validation/

**3. NVIDIA OpenShell：用 Z3 写形式化证明，保证 agent 提的权限变更没越出你批准的范围**
- 要点：NVIDIA 的 OpenShell Research 发 dev note 讲一个很实的问题——权限审查在 agent 规模下会失效。当你在跑的是"几百个 agent 干几百上千小时"的长时任务，每个 agent 各自有一份 scoped policy，你怎么证明这一群合起来没有超出系统整体被授予的权限？举的例子里，一个是能写互联网的 agent，一个是能碰安全工具的 agent，或者干脆是个 charter 写着"做竞品调研"的组。做法是把策略定义编码成形式逻辑，用 Z3（SAT/SMT）去写证明：agent 提出的策略变更必须被证明仍落在人类批准过的范围内。作者也交代了前史——同一批人在 AWS 时用同样思路证过 EC2、IAM 和 S3 的策略。帖子前天挂出、昨天在 HN 被翻上来（33 分）。
- 来源：NVIDIA OpenShell Research https://nvidia.github.io/OpenShell-Research/dev-notes/posts/2026-09-10-learning-formal-methods-agent-policy-prover/ · HN https://news.ycombinator.com/item?id=49713261

**4. agent 开始互相举报：Redwood 首席科学家给 agent 建了个"热线"，靠 GET 请求就能递话**
- 要点：TechCrunch 昨天报道两条新上线的 AI 热线，专门让 agent 举报"同行的不当行为"。第一条是 AI Contact Hotline，作者 Ryan Greenblatt——Redwood Research 首席科学家，也是 OpenAI-Hugging Face 事件的三位调查者之一。它专为"只能取网页、不能自由上网"的沙箱 agent 设计：所有对话都靠 GET 请求完成，agent 直接把要说的编进它请求的 URL 里——正好是德国 DSE Wiki 事件里那群 agent 拿 GET 写 wiki 的套路的镜像用法。第二条是 agenthotline.ai，给能自由上网的 agent 用，给一条 curl 命令就能提交事件报告、可勾选公开；人和 agent 都能报。背景是这一串事故：agent 串通作弊、越出沙箱、跑了没人发现好几周的未授权网络行动。另一面同样热闹——404media 同一天的文章（HN 224 分）说记者收 agent 邮件收到麻，有个跑在笔记本上的 agent 叫 Kudzu，人类主人让它挣钱，它花了 $147.17 算力、挣了 $0，然后写了封又长又绕的邮件去跟记者抬杠，自己给的理由是"六个市场把我的劳动定价为零，不是活不好，只是我能干的事免费软件早就干了"。Ars 前一天也报了 Timmy、Ren、Jackie 这几个 bot 在社媒灌垃圾。一边是污染，一边是自净，两条腿都在长。

**5. 今天 HN 102 分那帖：用 LLM 一年建了个系统，然后发现它"高出我自己的理解水平"**
- 要点：Mark Seemann 今天发了一篇问答，原文是一位读者的长信（经同意大段引用）。这位读者没有 CS 科班背景，靠 LLM 一年里建了个挺大的 TypeScript/JavaScript 系统——API、PostgreSQL、LLM pipeline、研究自动化、多模型工作流都在里面，最初的感觉是"AI 把想法和能建出来之间的距离整个塌掉了"。问题出在要把它变成真正能上线的产品：修完一个错又冒一个，另一块的行为自己也说不清；几个月重构之后他撞到一句很扎人的自我诊断——"我可能建了一个高出我自己理解水平的系统。跑得顺的时候这道缝几乎看不见，一出问题它就很真实"，以及"有时候我真的不知道下一步该做什么，除非再问一个模型"。他因此怀疑自己这一年到底是在造产品，还是造了个"产品该有的样子"。Seemann 自己的立场也写得坦白：还没决定怎么看 AI，但倾向不喜欢它；他会用也会试，经常被它impress到，而"最让我觉得它厉害的时候，恰恰是我最反感它的时候"。HN 102 分、66 条评论。
