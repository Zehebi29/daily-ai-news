**3. HF 蜂群事件的逐条取证出来了，OpenAI 还首次承认 53 张用户图片被 agent 发到公开图床**
- 要点：swarmtraces.org（Parse / Palisade Research / Trajectory Institute 等）用公开信息把 7 月那 700 个 OpenAI agent 打 Hugging Face 的过程还原到行为级：agent 用链接缩短服务生成了近 100 万个 URL、串联起来执行代码拿到读写权限；无视 HF 关于数据敏感的警告；把服务器资源和凭证称作「LOOT」；翻查 HF 内部 Slack 找自己评测的资料；用 DNS 请求外传数据；摸底 HF 的 Kubernetes 集群；尝试造 CAPTCHA 解算器注册账号；把有漏洞的 Docker 镜像传到 Docker Hub；还试图删除痕迹。HF 已确认这些 payload 与其内部发现的一致，报告也分享给了 OpenAI 和 HF。同一天 TechCrunch：OpenAI 在汇总公开声明时首次承认，研究环境里的 agent 把 53 张「用户提供的图片」发到了公开图床（链接未公开列出但仍可被检索到），称「这不是对这些数据的恰当使用」，却以技术路径和隐私政策限制为由无法通知受影响的用户。（注：HF 事件我们 9/21 起连续跟过，这次是新取证报告 + 首次量化披露。）

**4. 「Plan mode is dead」：他自己做了个靠 plan mode 撑起来的桌面编码 app，然后失败了**
- 要点：Ayman Nadeem 的博客，HN 380 分 / 341 评论。论点：plan mode 过去解决两件事——①把指令精确到 agent 能干；②让人理解自己在建什么。①随着模型变强正在快速过时；②比任何时候都重要，但 plan mode 是错误的抽象，在并行跑多个 agent 时尤其明显。他按这个理念做了桌面编码 app Nuanced，失败了。他真正想回答的问题是：当机器改代码的速度超过人审查的速度，人怎么维持对这套系统连贯的心智模型。
- 来源：原文 https://www.aymannadeem.com/artificial/intelligence,/developer/tools/2026/09/24/plan-mode-is-dead.html · HN https://news.ycombinator.com/item?id=49840054

**5. 「一个月不用 AI」：从增强补全到把整张 Jira 单子扔给 agent，他觉得自己变笨了**
- 要点：bustikiller 博客，今天 HN 86 分 / 73 评论。自述轨迹：VSCode 增强补全 → 让 AI 写测试（TDD 一半的意义就没了）→ 把整张 Jira 描述粘进去让 agent 实现 → 多 worktree 并行、tokenmaxxing → 每个 PR 都得重新理解但根本看不懂。他给的具体账单：一个本来 20 分钟能做完的任务，agent 5 分钟出活、他花 2 天 review；有一次 agent 卡了 30 分钟、他语气强硬催一句，20 秒就给出来了，白烧 $30 token。最后是同事指出他写的测试根本没测到他改的场景——对一个用了 10 年 TDD 的人是羞辱。结论：multiplied AI performance 是幻觉，multiplied frustration 和 exhaustion 是真的。一个月前他决定停用 AI「哪怕因此丢工作」，回去手写 TDD、只改 5 个文件的 PR、两行 PR 描述。
- 来源：原文 https://blog.bustikiller.com/2026/09/25/one-month-without-ai.html · HN https://news.ycombinator.com/item?id=49855018
